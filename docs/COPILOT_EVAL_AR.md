## ٦. الأمان والسجل أثناء التقييم

- كل نداء مسجَّل في `llm_audit` تحت المستخدم `eval:extract` والمنشأة `org_madar_eval` (35 صفاً، لا أخطاء).
- الصور والملفات الممسوحة (11 نداءً) مرّت كلها بمسار الموافقة الحقيقي (`uploadDocument` → `recordConsent` → `requireConsent`)، وكل صف `imageSent=true` يحمل رقم موافقة. صفر إرسال بلا موافقة.
- النص الذي يغادر إلى المزوّد مُخفًى بالبوابة نفسها التي يستخدمها الموظفون (لا مسار جانبي؛ يثبته حارس `no-bypass-llm`).
- عداد الاستخدام اليومي للمستخدم `eval:extract` بعد التشغيل: 401,448 رمزاً من سقف 600,000 — تشغيل كامل واحد في اليوم يكفي، والثاني في اليوم نفسه يحتاج رفع `COPILOT_DAILY_TOKEN_CAP` للجلسة (`npx dotenv -e ../../.env -v COPILOT_DAILY_TOKEN_CAP=2000000 -- npx ts-node --transpile-only -P tsconfig.jest.json scripts/eval-extract.ts`).

1. **الاسم الإنجليزي بين قوسين (#5):** قاعدة تنظيف في مُقيّم اسم المورد/العميل تُزيل القوسين إذا كان ما بينهما لاتينياً وتضعه في `nameEn` — سطر في `src/extract/schemas/common.ts`، ويُقاس بالتشغيل التالي.
2. **كلمة الصنف المحذوفة (#3):** إبقاء الاسم كما طُبع في المستند عند وجوده في النص الأصلي (المطابقة بالكتالوج لا تتأثر).
3. **المحتجزات في الصورة (#2):** تعليمة في برومبت العقد: «إن نصّ المستند على عدم وجود محتجزات أو دفعة مقدمة فاكتب 0 لا فراغاً».

## ٨. كيف تُعيد التشغيل

من `apps/copilot` ومع `ANTHROPIC_API_KEY` و`COPILOT_DATABASE_URL` في `.env` الجذر:

```bash
npm run eval:extract
```

تدفق واحد: `npm run eval:extract -- customer_contract`. التقرير يُكتب في `test-results/extract/<flow>-<stamp>.json` وصف في `eval_runs` تقرأه شاشة `/metrics`.

إعادة بناء المستندات بعد تعديل مصادرها (`eval/extract/<flow>/src/*.html`): `powershell -ExecutionPolicy Bypass -File scripts/eval-extract-docs.ps1 -Flow <flow> [-Name <file>]` ثم `npm run eval:extract:photos -- <flow>` للصور و`npm run eval:extract:scans -- <flow>` للنسخ الممسوحة.
