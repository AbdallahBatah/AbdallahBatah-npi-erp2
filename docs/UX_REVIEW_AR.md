# مراجعة شاملة لسهولة الاستخدام — نظام NPI للطاقة الشمسية

**التاريخ:** 2026-07-26
**المنهجية:** تدقيق كود لكل صفحات الويب (3 مسارات متوازية: المبيعات، التنفيذ، التشغيل والمالية) + جولة حية في المتصفح بعين مستخدم بسيط غير متخصص.
**الخلاصة:** البنية الوظيفية والمحاسبية ممتازة، لكن التجربة الحالية مصممة لمن بناها لا لموظف مكتب عادي. توجد **8 علل قاتلة** تجعل الاستخدام اليومي لغير المتخصص شبه مستحيل، تتقدمها: الفشل الصامت، وغياب أي تأكيد أو إشعار، والمصطلحات المحاسبية/التقنية الخام.

## المستوى الأول — قاتلة (تمنع الاستخدام الفعلي)

### 1. الفشل الصامت في معظم أزرار الحفظ والاعتماد
أكثر من 20 عملية كتابة عبر النظام مكتوبة بنمط `try { … } finally { setBusy(false) }` **بدون `catch`**: إذا رفض الخادم الطلب يتوقف المؤشر، تبقى النافذة مفتوحة، ولا تظهر أي رسالة. المستخدم البسيط سيضغط الزر مراراً ظناً أن الشبكة بطيئة.

أخطر المواضع:
- **إصدار الفاتورة إلى ZATCA** — `invoices/[id]/page.tsx:64-72` (فشل الإرسال الضريبي = لا شيء يظهر)
- ترحيل قيد الاعتراف بالإيراد — `finance/page.tsx:84-92`
- إنشاء عميل محتمل/فرصة/مشروع/مورد/أمر شراء — كل صفحات الإنشاء
- التركيب والتحويل في الأصول — `assets/page.tsx:77-98`

**العلاج:** توحيد كل الطلبات في مغلف `act()` واحد (موجود أصلاً في `assets/page.tsx:59` لكنه شبه غير مستخدم) يعرض الخطأ بجوار الزر.

### 2. لا يوجد أي إشعار نجاح في النظام كله
لا يوجد toast/snackbar إطلاقاً (البحث عن `toast`/`alert(`/`confirm(` = صفر نتيجة). بعد تسجيل دفعة أو إصدار فاتورة أو تحويل عميل، الإشارة الوحيدة هي تغيّر صامت في جدول. مع غياب تعطيل الأزرار أثناء التنفيذ في مواضع عدة (تحويل عميل محتمل، إنشاء عرض من فرصة، توليد فاتورة من مرحلة) فالنتيجة الحتمية: **نقرات مزدوجة تنتج عروضاً وفواتير مكررة**.

### 3. «جارٍ التحميل…» إلى الأبد عند أي فشل
لا `.catch()` على أي طلب قراءة في كل الصفحات، ولا معالجة لانتهاء الجلسة (401): من يترك التبويب مفتوحاً ليلة يعود لنظام «معطل» كل أزراره صامتة ولا يُعاد إلى صفحة الدخول. **تم التأكد حياً:** فتح رابط فاتورة غير موجودة يعرض «جارٍ التحميل…» بلا نهاية. كذلك صفحة المشتريات تجمع 6 طلبات في `Promise.all` واحد — فشل واحد يفرغ الجداول الستة.

### 4. رسائل الخطأ (حين تظهر) إنجليزية تقنية خام
`lib/api.ts:39-44` يمرر نص الخادم كما هو. أمثلة حقيقية سيقرؤها موظف عربي:
- `Line MOD-550: receiving 40 exceeds remaining 12`
- `Serialised items are replaced via the RMA flow (W7), not bulk parts` (يذكر رقم موجة تطوير داخلية!)
- `Missing GL account 2010 — re-run the seed` (تعليمات مطوّرين)
- انقطاع الشبكة يظهر `Failed to fetch`، وصفحة خطأ HTML من بوابة تكسر `JSON.parse` وتعرض `Unexpected token '<'`

**العلاج:** أكواد خطأ آلية من الـ API تُترجم في `messages.ts`، مع فرع «تعذّر الاتصال بالخادم».

### 5. صفر رسائل تأكيد على عمليات لا رجعة فيها
كلها بنقرة واحدة بلا سؤال ولا شرح للعواقب:
- إرسال الفاتورة إلى ZATCA (التزام ضريبي قانوني)
- التحقق من مرحلة عقد (يفعّل الاعتراف بالإيراد)
- اعتماد أمر تغيير (يعدل قيمة العقد) واعتماد مستخلص (يرحّل قيداً)
- ترحيل فاتورة مورد، الإفراج عن محتجزات، تسوية PPA (تنشئ فاتورة حقيقية)
- إغلاق/إلغاء أمر عمل، تركيب رقم تسلسلي (ينشئ أصلاً ومحطة تلقائياً)
- زر «محاكاة» القياس في رأس الصفحة يكتب 14 يوم قراءات وينشئ إنذارات وأوامر عمل — بنقرة واحدة

### 6. طريق مسدود: لا توجد صفحة عملاء أصلاً
إنشاء فرصة **يتطلب** اختيار عميل من قائمة، لكن لا توجد صفحة عملاء في النظام (المفتاح `nav.customers` معرّف وغير مستخدم). الطريق الوحيد لإنشاء عميل هو تحويل عميل محتمل — وهذا غير مذكور في أي مكان. المستخدم الجديد يقف أمام قائمة فارغة «—» بلا مخرج.

### 7. الحقول الإنجليزية إلزامية تحظر الموظف العربي
إنشاء أمر عمل/خطة صيانة/أمر تغيير/عقد باطن/مطالبة ضمان يتطلب نصاً إنجليزياً إلزامياً والزر معطّل بلا تفسير. **والأسوأ:** نافذة إنشاء العقد `proposals/[id]/page.tsx:122-130` **تُسقط بصمت** كل مرحلة وصفها الإنجليزي فارغ — موظف عربي يملأ الحقول العربية فقط ينشئ عقداً **بلا مراحل** أي بلا ما يُفوتر عليه، دون أي تحذير.

### 8. أوامر الصيانة الوقائية لا يمكن إغلاقها
علتان متراكبتان: (أ) `generateDue` لا ينسخ قائمة التحقق من قالب الخطة إلى أمر العمل، فتفتح نافذة الإنجاز **فارغة**؛ (ب) مطابقة البنود الإلزامية تتم بالنص الإنجليزي `label === m.labelEn` (`fsm.service.ts:330`) بينما الفني يكتب بالعربية — فالنتيجة رفض دائم برسالة إنجليزية `Mandatory checklist item not done: …`. كذلك مؤشر الشطب معكوس: البنود **غير المنجزة** هي المشطوبة (`workorders/[id]/page.tsx:306`).

## المستوى الثاني — كبيرة (تربك أو تضلل)

### المصطلحات والجرعة المحاسبية
- **«قيمة خط الأنابيب»** في لوحة المعلومات — ترجمة حرفية لـ pipeline توحي بأنبوب نفط. الصواب: «قيمة الفرص المتوقعة». *(تأكدت حياً)*
- اختصارات بلا شرح في كل مكان: WBS، GRN، RMA، PR، SLA، IFRS-15، BOM، POC، CSID، SCADA، UBL، SKU، UoM
- **أرقام حسابات دفترية في نصوص المساعدة**: «حساب 1150 (أصل عقد) أو 2400 (إيراد مؤجل)»، «مدين WIP + ضريبة مدخلات / دائن ذمم موردين + محتجزات دائنة (2050)» — نصوص لمحاسب محترف موضوعة أمام الجميع *(تأكدت حياً في صفحة المالية)*
- اختصار مخترع **«ك.و.ذ»** لـ kWp لن يفكه أحد؛ «التصعيد السنوي» توحي بتصعيد شكوى لا زيادة تعرفة
- «append-only» إنجليزية داخل جملة عربية
- UUID وهاش الفاتورة وPIH والختم الرقمي معروضة بارزة فوق بيانات العميل — مستخدم عادي لا يحتاجها أبداً (تُطوى خلف «تفاصيل تقنية»)

### تسريبات نصوص خام على الشاشة
- الدور الوظيفي في الشريط الجانبي يظهر كمفتاح خام (`ADMIN`, `SALES_MANAGER`)
- وضع الإرسال `CLEARANCE`/`REPORTING` بلا ترجمة
- الحالتان `WITHHELD` و`RELEASED` غير معرّفتين في STATUS_META → تظهران خامتين في صفحة الفاتورة
- عناوين مخلوطة حرفياً «التاريخ / Date» في 3 صفحات
- خانة المرحلة في الفرص تعرض النص مرتين («استكشاف استكشاف»)

### الجداول: لا بحث ولا فلترة ولا ترقيم صفحات
ولا جدول واحد فيه بحث أو فرز أو ترقيم (`common.search` معرّف وغير مستخدم)، والـ API يرجع كل الصفوف بلا حد. جدول الوحدات التسلسلية سيصبح 10,000 صف لمحطة 5MW في DOM واحد. بعد سنة استخدام ستتجمد صفحة العملاء المحتملين.

### استلام البضائع بالتسلسلات — أخطر نموذج في النظام
- كل الأرقام التسلسلية في `textarea` واحدة، بلا عدّاد «12/40»، بلا كشف تكرار، بلا مدخل ماسح باركود؛ الكمية معبأة مسبقاً بالكامل فالحالة الافتراضية للنموذج فشل مضمون برسالة إنجليزية واحدة شاملة
- **نقرة واحدة خارج النافذة تمحو 300 رقم مكتوب** بلا تحذير (إغلاق فوري على النقر الخارجي، بلا حارس تعديلات، في كل نوافذ النظام)
- لا اختيار لموقع الاستلام رغم أن الـ API يدعمه — البضاعة تهبط في «أول مستودع» صامتاً
- زر استلام بكميات صفرية لا يفعل شيئاً إطلاقاً

### حالات فارغة وصفحات بلا مدخل
- كل جدول فارغ يعرض «لا توجد بيانات» بلون تباينه 1.9:1 (شبه مخفي) بلا خطوة تالية
- صفحات العروض والعقود والفواتير **بلا زر إنشاء وبلا تفسير** (تُنشأ من صفحات أخرى — لا أحد يخبر المستخدم)
- نافذة «مشروع جديد» بلا عقود متاحة تعرض جملة ميتة بلا رابط لإنشاء عقد
- مخطط المسار في لوحة المعلومات ديكوري: غير قابل للنقر، وأسهمه «→» تشير يميناً بينما التدفق في RTL يسير يساراً *(تأكدت حياً)*
- لا يوجد أي إرشاد أول استخدام أو قائمة «ابدأ هنا» رغم أن التسلسل عميل محتمل→فرصة→عرض→عقد→مشروع إلزامي

### الصلاحيات والأمان
- `can()` موجودة وغير مستخدمة في أي صفحة: كل مستخدم يرى كل الأزرار بما فيها الإرسال الضريبي، ويكتشف منع الصلاحية عبر 403 إنجليزي (لا يُعرض أصلاً بسبب العلة 1)
- بيانات دخول المدير معبأة مسبقاً ومطبوعة على شاشة الدخول (مقبول للتطوير، يجب إزالته خلف علم بيئة قبل أي عرض)
- لا «نسيت كلمة المرور» ولا أي مسار استرداد

### لا واجهة موبايل إطلاقاً
الشريط الجانبي ثابت 264px بلا أي نقطة كسر ولا قائمة همبرغر — النظام غير قابل للاستخدام على جوال أو آيباد، بينما الاستلام في المستودع وإنجاز أوامر الصيانة عمل ميداني بطبيعته.

### أخطاء تفصيلية مضللة
- مخطط القياس: بلا محور Y، بلا تواريخ على X (تظهر hover فقط — مستحيلة على اللمس)، عمود «المتوقع» رمادي 1.2:1 شبه مخفي، وأرضية 3px تجعل يوم الإنتاج الصفري يبدو منتجاً
- PR% بلا معيار (83% جيد أم كارثة؟) ولونه لا يصبح أحمر أبداً حتى عند 30%
- هامش الربحية السالب يُعرض بنفس لون الموجب
- زر «ترحيل قيد الاعتراف» لا يعرض المبلغ الذي سيُرحّل
- إقرار الضريبة يعرض أرقاماً بلا ذكر الفترة التي تغطيها
- إجمالي أمر الشراء يظهر كتعبير غير مجموع «40,000 + 6,000» والمستخدم يجمع ذهنياً، والـ 15% ثابتة في كود الواجهة
- سعر البيع يُعبأ تلقائياً بـ**التكلفة** عند اختيار الصنف دون تنبيه
- ساعات العمالة: حقلان بلا عنوان بقيم افتراضية سحرية (1 و80) والأجرة 80 ر.س/ساعة ثابتة في الكود
- المدفوعات: لا حد أقصى بقيمة المتبقي، لا زر «سداد كامل»، لا حقل تاريخ استلام
- نافذة تسوية PPA لا تعرض أي عقد تُسوّى، ومداها الافتراضي 14 يوماً بينما الرسم الشهري الثابت يُطبق كاملاً
- لا حذف ولا تعديل لأي شيء أُنشئ بالخطأ، ولا شاشة تقول ذلك — أول خطأ للمبتدئ دائم

## المستوى الثالث — إتاحة وقراءة (WCAG)

| العلة | الموضع | الأثر |
|---|---|---|
| نص فارغ/تحميل `text-slate-300` | تباين ≈1.9:1 (الحد 4.5:1) | شبه مخفي |
| رؤوس الجداول 11px `slate-400` + `uppercase tracking-wider` | كل الجداول | تباين 2.6:1 والـ tracking يفكك حروف العربية المتصلة |
| placeholder `slate-300` | كل الحقول | إرشادات غير مقروءة (وبعض الحقول لا عنوان لها سواه) |
| عناوين أقسام الشريط الجانبي `slate-600` على أسود | layout | غير مرئية |
| لا `htmlFor`/`id` في `Field` | كل النماذج | النقر على العنوان لا يركّز الحقل؛ قارئ الشاشة يقرأ حقولاً بلا اسم |
| النوافذ بلا `role="dialog"`/Esc/focus-trap | كل النوافذ | لوحة المفاتيح تهرب خارج النافذة |
| صفر `aria-label` في المشروع | أزرار ✕ ✓ والخروج والإيموجي | غير معلنة لقارئ الشاشة |
| أهداف لمس 20-28px | أزرار الجداول والإغلاق | دون حد 44px |
| إيموجي وظيفية (🔢 = متسلسل!) | مواضع كثيرة | معنى حرج بلا شرح، وعرض غير متسق |
| لا `aria-current` على الرابط النشط | الشريط الجانبي | اللون وحده يحمل الحالة |

**ملاحظة التقويم:** في كروم الحالي `ar-SA` يُحسم ميلادياً *(تأكدت حياً)*، لكن هذا غير مضمون في Safari/ICU أقدم حيث الافتراضي هجري أم القرى — يجب تثبيت `-ca-gregory` في `format.ts` احترازياً.

## ما هو جيد فعلاً (يُحافظ عليه)

- رسالة خطأ الدخول عربية وواضحة «بيانات الدخول غير صحيحة» *(تأكدت حياً)* — لكنها تُعرض أيضاً عند تعطل الخادم (تضليل: المستخدم يظن كلمة مروره خاطئة)
- شارات الحالة StatusBadge ثنائية اللغة بنقاط ملونة — نمط ممتاز يحتاج فقط سد الفجوات
- الأرقام غربية موحدة والعملة «ر.س.» بالعربية
- الشريط الجانبي المقسم بعناوين عربية واضحة، وتمييز الصفحة النشطة
- التسلسل الهرمي للألوان (نجاح أخضر/تحذير كهرماني/خطر وردي) متسق

## خطة إصلاح مقترحة (بالترتيب)

**الحزمة أ — شبكة الأمان (الأثر الأكبر، أسبوع):**
1. مغلف `act()` موحد لكل الطلبات + مكوّن Toast عام (نجاح/فشل)
2. `catch` على كل GET + شاشة خطأ مع «إعادة المحاولة» + معالجة 401 بإعادة توجيه للدخول
3. أكواد خطأ من الـ API مترجمة في `messages.ts` + فرع «تعذّر الاتصال»
4. مكوّن `ConfirmDialog` موحد للعمليات اللارجعية الثمانية بصياغة عواقب عربية واضحة
5. تعطيل كل زر أثناء التنفيذ (منع التكرارات)

**الحزمة ب — فك الحصار عن المستخدم العربي (أيام):**
6. جعل الحقول الإنجليزية اختيارية (نسخ تلقائي من العربية) + **إصلاح إسقاط المراحل الصامت في إنشاء العقد**
7. إصلاح الصيانة الوقائية: نسخ قالب التحقق إلى أمر العمل + مطابقة بالمعرّف لا بالنص الإنجليزي + عكس الشطب
8. صفحة عملاء + «＋ عميل جديد» داخل قائمة الفرص
9. سد فجوات STATUS_META (WITHHELD/RELEASED) وترجمة الدور ووضع الإرسال

**الحزمة ج — الإرشاد والوضوح:**
10. حالات فارغة لكل جدول بجملة غرض + زر الإجراء الأول؛ نصوص «تُنشأ العروض من صفحة الفرص» مع روابط
11. استبدال المصطلحات: «قيمة الفرص المتوقعة»، شرح أول ظهور لكل اختصار، طي UUID/الهاشات خلف «تفاصيل تقنية»، نقل أرقام الحسابات لعرض المحاسب فقط
12. بحث + فلترة حالة + ترقيم صفحات (ابتداءً بالأصول والعملاء المحتملين) مع `take/skip` في الـ API
13. نموذج استلام التسلسلات: صف لكل وحدة أو مدخل ماسح + عداد حي + كشف تكرار + حارس «تجاهل التغييرات؟» في النوافذ

**الحزمة د — الإتاحة والجوال:**
14. رفع التباين (slate-500+ بدل 300/400)، حذف uppercase/tracking للعربية، 12px حداً أدنى
15. `htmlFor`/aria/Esc/focus-trap + استبدال الإيموجي الوظيفية بمكوّن Icon
16. طي الشريط الجانبي دون lg + عرض بطاقات للجداول على الشاشات الصغيرة
